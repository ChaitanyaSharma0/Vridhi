02
NLP Engine & Skill Ontology Layer
Raw text → Extracted skills → ESCO mapping → Semantic embeddings → ChromaDB
3 Stages
i This is the CORE ENGINE of SkillForge. It takes raw unstructured text (job descriptions, resumes, syllabi) and extracts structured skill data. It uses ESCO taxonomy for standardization and sentence-transformers for semantic embeddings. Output goes to both MongoDB (structured) and ChromaDB (vector store).
▼
🏷️
ESCO Skill Taxonomy
i ESCO (European Skills/Competences) is an official EU skill classification with 500+ standardized skills. We use it to normalize skill names — e.g., "ML", "machine learning", "Machine Learning (ML)" all map to the same canonical skill.
500+ standardized skills from the official EU ESCO framework. Normalizes variations ("ML" → "Machine Learning") to a canonical taxonomy.
⚙️ Normalization Example
Input variations:
"ML", "machine learning", "Machine Learning (ML)", "M.L."

→ Canonical output:
"Machine Learning" (ESCO: S1.4.2)
🔍
Skill NER (Hybrid Extraction)
i Two-pass extraction: (1) Regex/dictionary match against ESCO taxonomy for known skills, (2) LLM pass via Groq for skills the dictionary missed. This catches both common skills and emerging/niche ones.
Two-pass extraction: regex/dictionary match against ESCO + LLM-assisted (Groq) extraction for emerging skills the dictionary misses.
📥 Input (Raw Job Description)
"Looking for a senior engineer with
 experience in Python, TensorFlow,
 ML pipelines, A/B testing, SQL,
 and Apache Spark. Must have
 strong statistical analysis skills."
↓
📤 Output (Extracted Skills Array)
Pass 1 (Regex/ESCO):
["Python", "TensorFlow", "SQL", "Apache Spark"]

Pass 2 (LLM/Groq):
["ML Pipelines", "A/B Testing", "Statistical Analysis"]

Final merged:
["Python", "TensorFlow", "SQL", "Apache Spark",
 "Machine Learning", "A/B Testing",
 "Statistical Analysis"]
// 7 skills extracted, all ESCO-normalized
🧮
Semantic Embeddings
i Uses sentence-transformers (MiniLM-L6-v2) to convert skills and text chunks into 384-dimensional vectors. These vectors capture semantic meaning — "Python" and "pandas" are closer together than "Python" and "Kubernetes". Stored in ChromaDB for fast semantic search.
Sentence-transformers (MiniLM-L6-v2) converts text → 384-dim vectors. Stored in ChromaDB vector store for semantic search and RAG retrieval.
⚙️ Embedding Example
Input: "Python programming language"

Output vector (384 dims):
[0.0234, -0.1892, 0.4521, 0.0891,
 -0.3201, 0.1567, ..., 0.0423]

// Cosine similarity:
// "Python" ↔ "pandas" = 0.82
// "Python" ↔ "Kubernetes" = 0.31
// "Python" ↔ "Cooking" = 0.05

03
Intelligence & ML Layer — 4 Modules
SkillRadar • TalentMatch • CompIntel • CurriculumSync + Knowledge Graph + MLflow
4 Modules
i The analytical core. Four intelligence modules consume processed data from Layer 2. Each module has specific ML models trained on Indian data. This layer also includes the Knowledge Graph (NetworkX), t-SNE visualizations, and MLflow experiment tracking.
▼
📈
SkillRadar™ — Trend Forecaster
i Groups job postings by month, counts skill mentions per role, classifies trends as rising (>15% growth), stable, or declining (>15% drop). Uses ARIMA/Linear Regression for 6-month forecast. Powers the "What skills are trending?" answer.
Tracks skill demand trends over time. Forecasts rising & dying skills per role and city. Uses ARIMA + Linear Regression on temporal posting data.
📤 Sample Output
Rising (Data Scientist, Bangalore):
 • LangChain: +340% (6mo)
 • MLOps: +89%
 • Kubernetes: +45%

Dying:
 • Hadoop: -52%
 • jQuery: -67%
🎯
TalentMatch — Gap Engine
i Takes a user's resume skills and compares against the "ideal skill vector" for their target role (aggregated from all postings). Computes match % using cosine similarity on embeddings. Ranks missing skills by how much they'd improve the match + their salary impact from CompIntel.
Resume → skill extraction → cosine similarity against target role's ideal skill vector → match %, ranked gaps with salary impact.
📥 Input
User Skills: Python, SQL, pandas, NumPy
Target Role: Data Scientist
↓
📤 Output
Match Score: 42%

Top skills to learn:
1. Machine Learning → +18% match | +₹2.1L
2. TensorFlow → +14% match | +₹1.8L
3. Statistics → +12% match | +₹1.2L
💰
CompIntel™ — Salary Predictor
i Multi-model ensemble (RandomForest + XGBoost + GradientBoosting) trained on Indian salary data. Predicts salary from skills + experience + location. Features a "What-if" simulator and SHAP explainability showing which skills/factors drive the prediction up or down.
Ensemble model (RF + XGBoost + GBM) predicts salary from skills + exp + location. "What-if" simulator + SHAP explainability.
📥 Input
Skills: Python, SQL, ML, TensorFlow
Experience: 5 years
Location: Bangalore
↓
📤 Output
Predicted Salary: ₹22.4 LPA
Confidence: 85% (₹19.8L - ₹25.1L)

What-if: Add "Kubernetes"
New prediction: ₹25.1 LPA (+₹2.7L)

CurriculumSync — Alignment Scorer
i Compares extracted skills from university syllabi against top demanded skills from job postings. Scores each course by overlap with market demand. Generates a downloadable PDF gap report showing which courses are aligned and which need updating.
Scores university courses against market demand. Auto-generates PDF gap reports for academic deans to facilitate curriculum updates.

04
Agentic AI + Presentation Layer
RAG Career Counselor • Streamlit Dashboard • FastAPI + OpenAPI Docs
3 Channels
i The delivery layer. Users interact here. The Agentic RAG career counselor uses Groq LLM + ChromaDB + function calling to autonomously route queries to the right intelligence module. Streamlit provides the interactive dashboard. FastAPI exposes all modules as RESTful endpoints.
▼
🤖
Agentic RAG Career Counselor
i This is NOT a simple chatbot. It uses agentic architecture: (1) User query comes in, (2) Groq LLM analyzes intent, (3) LLM decides which tool/module to call via function calling (TalentMatch, CompIntel, SkillRadar), (4) Module returns data, (5) LLM formulates grounded response using ChromaDB context. Fully autonomous routing — no hardcoded if/else.
Autonomous, data-grounded guidance via Groq LLM + ChromaDB retrieval + function calling. Routes queries to intelligence modules without hardcoded rules.
⚙️ Agentic Pipeline Flow
Step 1: User Query → "I know Python and SQL.
    How well do I match Data Scientist?"

Step 2: Groq LLM analyzes intent
    → Decides: call TalentMatch
       + call CompIntel

Step 3: Function Calling executes
    → TalentMatch returns: match=42%,
      gaps=[ML, TensorFlow, Stats]
    → CompIntel returns: +₹4.5L impact

Step 4: ChromaDB retrieves context
    → "ML demand grew 23% in India..."

Step 5: Groq generates final response
    → Grounded in REAL data, not hallucinated
